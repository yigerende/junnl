# junnl 终端启动说明

本文说明如何在终端启动 / 停止 junnl（二进制名 `kiro-rs`）。

---

## 一、前置条件

- 已安装 Rust 工具链（`cargo`）。
- 项目根目录下有真实配置文件：
  - `config.json` —— 主配置（apiKey、adminApiKey、端口、代理等）
  - `credentials.json` —— 凭据
- 首次运行或代码更新后需要先编译（见下）。

> 配置文件不在 Git 仓库里，需手动准备：
> `cp config.example.json config.json` 后填入真实值。

---

## 二、编译

```powershell
# 在项目根目录
cargo build --release
```

编译产物：`target/release/kiro-rs.exe`（Windows）/ `target/release/kiro-rs`（Linux）。

> 调试用可以 `cargo build`（不带 `--release`），产物在 `target/debug/`，编译快但运行慢。
> 正式启动一律用 `--release`。

---

## 三、启动（Windows / PowerShell）

### 方式 1：用脚本（推荐）

```powershell
# 项目根目录执行
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

脚本行为：
- 若 `target/release/kiro-rs.exe` 不存在，会自动 `cargo build --release`。
- 后台启动（隐藏窗口），并把进程 PID 写入 `.junnl.pid`。
- 若已在运行，会提示「已在运行」，不重复启动。

### 方式 2：直接运行二进制

```powershell
# 前台运行（关掉终端即停止），日志直接打到控制台
.\target\release\kiro-rs.exe -c config.json --credentials credentials.json
```

参数说明：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-c` / `--config` | 主配置文件路径 | `config.json` |
| `--credentials` | 凭据文件路径 | 由配置/内置默认决定 |

不带任何参数时，默认读当前目录的 `config.json`：

```powershell
.\target\release\kiro-rs.exe
```

---

## 四、启动（Linux / macOS）

```bash
# 编译
cargo build --release

# 前台运行
./target/release/kiro-rs -c config.json --credentials credentials.json

# 后台运行（nohup，日志重定向到文件）
nohup ./target/release/kiro-rs -c config.json --credentials credentials.json > stdout.log 2>&1 &
```

---

## 五、停止

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File .\stop.ps1
```

脚本会按 `.junnl.pid` 停止进程；找不到 PID 文件时按进程名 `kiro-rs` 停止。

手动停止：

```powershell
Get-Process kiro-rs | Stop-Process -Force
```

### Linux / macOS

```bash
pkill -f kiro-rs
```

## 六、确认运行状态

```powershell
# Windows：进程
Get-Process kiro-rs

# 端口监听（端口以 config.json 的 port 为准，默认 8991）
Get-NetTCPConnection -LocalPort 8991 -State Listen
```

```bash
# Linux
ps aux | grep kiro-rs
ss -ltnp | grep 8991
```

启动成功后：
- API 端点：`http://<host>:<port>`（如 `http://127.0.0.1:8991`）
- Admin 后台：`http://<host>:<port>/admin`

## 七、日志

junnl 自带日志落盘（控制台 + 按天滚动 JSON 文件）：

- 日志目录：默认项目根下 `logs/`，可用环境变量 `JUNNL_LOG_DIR` 覆盖。
- 文件名：`logs/app.<UTC日期>`，每天一个，JSON 格式（可 `jq` 解析）。
- 留存天数：默认 3 天，可用 `JUNNL_LOG_RETAIN_DAYS` 调整。
- 日志级别：用 `RUST_LOG` 环境变量控制控制台/内存面板，默认 `info`。
- **落盘文件默认只记录 WARN 及以上**（warn/error），避免 INFO 噪音撑爆磁盘
  （实测 INFO 全量落盘约 10GB/天）。实时 INFO 看控制台或「运行日志」页。
  排查时用 `JUNNL_LOG_FILE_LEVEL=info`（或 `debug`）临时让文件也落全量。
- Admin 后台「运行日志」页可实时查看（SSE）+ 搜索 + 按 request_id 筛选。
- 「运行日志」页顶部显示**落盘目录的绝对路径**，并提供「导出当天」按钮一键下载当天日志文件。

> **⚠️ 找不到日志文件？** `logs/` 是**相对「当前工作目录(cwd)」**的相对路径，
> cwd 取决于进程的启动方式，**不是二进制所在目录**：
> - 用 `start.ps1` 启动：cwd 锁定为项目根，文件落在 `项目根/logs/`。
> - 用 systemd / nohup / 脚本从别的目录启动：文件落在那个目录的 `logs/` 下。
> - **Docker**：文件落在容器内 `/app/logs`，宿主机看不到，且容器重建即丢。
>   需在 `docker-compose.yml` 增加挂载，例如 `- ./logs/:/app/logs/`。
>
> 不确定落在哪时，打开「运行日志」页看顶部的「落盘目录」绝对路径，或设置
> `JUNNL_LOG_DIR` 指定一个固定的绝对路径，一劳永逸。

环境变量示例（PowerShell）：

```powershell
$env:RUST_LOG = "debug"
$env:JUNNL_LOG_DIR = "D:\junnl-logs"
$env:JUNNL_LOG_RETAIN_DAYS = "30"
.\target\release\kiro-rs.exe
```

环境变量示例（Linux）：

```bash
RUST_LOG=debug JUNNL_LOG_DIR=/var/log/junnl ./target/release/kiro-rs
```

## 八、常见问题

- **导入账号 / 验活失败，报 `error sending request for url (https...`**：
  通常是没开代理。junnl 验活要访问境外地址，需在 `config.json` 配 `proxyUrl`，或给凭据配置代理。

- **端口被占用**：改 `config.json` 的 `port`，或停掉占用进程。

- **改了代码不生效**：必须重新 `cargo build --release` 再启动；脚本只在二进制不存在时才自动编译，已存在则直接跑旧的。

- **改了前端（admin-ui）不生效**：前端通过 `rust-embed` 打进二进制，改了要先在 `admin-ui` 目录 `pnpm build`，再 `cargo build --release`。
